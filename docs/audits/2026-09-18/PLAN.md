# План исправлений и развития Blackboard Text

Основание: [аудит 18 сентября 2026](/Users/dameer/Desktop/code/blackboard-text/docs/audits/2026-09-18/REPORT.md), версия 2.2.0, commit f34cf90. Это план, исправления и новые возможности ещё не реализованы. Исходный код сохранён. Оценки — инженерная прикидка для одного разработчика, включая соответствующие проверки; это не срок обещанного релиза.

**Рекомендуемый порядок: безопасность → сохранность → корректность взаимодействия → чтение ссылок → новые возможности.** Для основной серии исправлений ориентир **7–11 рабочих дней**; весь баг-лист, включая узкие случаи и проверки на реальных браузерах, **9–14 дней**. Риски R-01…R-09 могут изменить объём. Суммы отдельных оценок не складываются механически: общие исправления и тесты перекрываются.

### A1. Безопасное чтение

- [ ] Зафиксировать минимальный допустимый HTML заметки: текст, используемое форматирование и явно разрешённые ссылки. Проверить, какие элементы реально создаёт текущий редактор.
- [ ] Создать отдельную политику reader: никакого исполняемого HTML или автоматических внешних загрузок.
- [ ] Проверять протоколы после нормализации; покрыть управляющие символы, HTML entities, SVG/MathML, CSS URL, srcset/poster и вложенные шаблоны.
- [ ] Согласовать CSP со статическим размещением. Не считать CSP единственным исправлением sanitizer.
- [ ] Тестировать настоящий DOM, а не заменять sanitizer тестовой регуляркой.
- [ ] Проверить легитимные bold/italic, списки, переносы, ссылки и рисунки из существующих backup.

**Готово, когда:** две исходные пробы из аудита не работают; нет исполнения и незапрошенных исходящих запросов; обычная опубликованная заметка сохраняет содержимое. До публичного исправления не добавлять новые возможности активной разметки.

### A2–A4. Сохранность данных

- [ ] Задать единый результат записи: конкретная транзакция успешна или ошибка дошла до вызывающего кода.
- [ ] Отделить восстановление очереди после ошибки от сообщения об успешности последней записи. flush не должен выдавать «всё сохранено» только потому, что очередь снова работоспособна.
- [ ] Сделать ошибку сохранения устойчивым состоянием с повтором и экспортом, сохраняющим актуальный DOM.
- [ ] Блокировать update activation при неудачной записи, не терять обработчик кнопки после неудачного повтора.
- [ ] До полной загрузки workspace держать ввод и lifecycle-save заблокированными.
- [ ] Валидировать import до мутаций; ID безопасно сопоставлять с DOM. Различать повреждённую страницу и корректную пустую заметку.
- [ ] После import/restore/смены владельца заново строить историю отмены и отменять отложенные снимки.
- [ ] Для legacy сначала определить версию геометрии, потом преобразовать её; не маркировать старое содержимое новым форматом заранее.
- [ ] Перед изменением схемы использовать экспорт/снимок; исходный Chrome storage сохранять.

**Готово, когда:** искусственная ошибка записи не приводит к потерянному тексту при обновлении; import с теми же ID не подтягивает старый Undo; отказ загрузки не записывает пустой DOM; штрих из commit 724d0cd имеет прежние 4 px. Корректные backup текущей версии продолжают импортироваться.

### A5–A7. Поведение и доступность интерфейса

- [ ] Привести Publish, Import и Restore к одному корректному модальному механизму. Предпочтение — верхний слой native dialog, если его применение совместимо с текущими стилями.
- [ ] Удерживать фокус, делать фон inert, возвращать фокус к исходной кнопке; проверить и мышь, и клавиатуру.
- [ ] Добавить выход из редактирования клавиатурой, сохранив Tab-отступы и IME.
- [ ] Устранить пересечения текста с постоянными панелями на 1280 и 1440 px; проверить прокрутку, большой шрифт и длинный page rail.
- [ ] В reader считать все смещения в одной системе координат. Ширина внешнего контейнера должна соответствовать viewport.
- [ ] Привязать чтение, запись и событие scroll к одному фактическому элементу.
- [ ] Разделить показ палитры и применение значения; исправить reset на DEFAULT_SETTINGS.
- [ ] В режиме read-only оставить действия просмотра/экспорта, блокируя запись.
- [ ] Исправить названия цветовых контролов, focus-visible и итоговый контраст служебного текста; проверить обе светлую и тёмную темы, затем все встроенные.

**Готово, когда:** воспроизведения из реестра больше не срабатывают; произвольное нажатие внутри кнопки диалога попадает в неё, а не в панель позади; текст/рисунок сохраняют взаимное положение. Для WCAG-проверки маленькие цели оценивать по действующему минимуму и исключениям; 44 px — улучшенная цель, не универсальная граница бага.

### A8. Версия и запасная блокировка

- [ ] Синхронизировать manifest из исходной папки, package и generated dist.
- [ ] Предпочтительный минимальный путь для fallback: документировать поддерживаемые Chrome/Edge с Web Locks, в неподдерживаемой среде не разрешать небезопасную запись.
- [ ] Если нужна поддержка fallback, отдельно спроектировать потерю lease, возврат после паузы и запрет дальнейшей записи. Не заявлять атомарность localStorage.

## Минимальная проверка каждого исправления

| Сценарий | Что должно быть проверено |
| --- | --- |
| Обычное письмо | Ввод, вставка, Undo/Redo, смена страницы, reload, настройки и штрихи. |
| Отказ диска/квоты | Ошибка видна; актуальное содержимое можно выгрузить; обновление не запускается. |
| Импорт | Корректная копия, тот же ID, одинаковые ID, кавычки/скобки в ID, null/число вместо страницы, пустые заметки, большой файл. |
| Восстановление | Snapshot до изменения, отмена подтверждения, restore, Undo после restore; изменения в других страницах не исчезают. |
| Старое расширение | Поддерживаемые исторические форматы, реальные chrome.storage API в отдельном тестовом профиле; исходная копия остаётся. |
| Чужой HTML | Настоящий DOM и сетевой журнал, не только сравнение строк. |
| PWA | Первая установка, офлайн после неё, ожидающая версия, успешный reload, отказ записи перед reload. |
| Несколько вкладок | Второй writer запрещён; чтение/экспорт доступны; передача владения не возвращает старую историю. |
| Reader | Текст/рисунки, заголовок/без заголовка, 1440/1280/390/320 px, DPR 1 и 2, выбор и копирование текста. |
| Доступность | Tab/Shift+Tab/Escape, VoiceOver, контраст основных тем, увеличение текста, reduce motion. |
| Артефакт | npm run verify на Node 22, старт обеих целей, версионность, отсутствие dev-страниц и доступные notices. |

Браузерные тесты добавлять там, где есть реальный отказ. Не нужны снимки каждого пикселя и тесты, просто повторяющие реализацию. После успешных профильных проверок не расширять матрицу бессистемно; идти к проверке готового артефакта.

## Выпуск и сохранение возможности отката

До распространения новой сборки нужны результаты A9 и проверка реальных Chrome/Edge. Перед миграционными изменениями — экспорт и сохранённый исходный профиль. Не удалять старые записи автоматически и не переключать идентичность установленного расширения.

Для PWA отдельно проверить ожидание worker и сохранность при Reload. Не выпускать исправленный JS под старым именем кеша без проверки update-пути; версия приложения, manifest и worker должны быть согласованы.

Публикация, push, PR, merge и deployment в рамках аудита не выполнялись. Готовый пакет исправлений должен быть сначала конкретно проверяемым локально; после этого подтверждается его распространение согласно правилам проекта.

## Что считать завершением плана

Очередь A завершена, когда у каждого из 22 BUG есть исправление, профильное подтверждение и результат проверки артефактов; условный BUG-13 может быть закрыт документированным отказом от небезопасного fallback. Ни один исправленный баг не считается закрытым только по чтению diff.

Очередь B завершена только для выбранных продуктовых пакетов и согласованных критериев. Её не требуется выполнять целиком, чтобы выпустить надёжную версию с исправлениями.
